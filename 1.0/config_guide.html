Configuration Guide#

Overview#

behav_utils uses a single YAML config file to map your experiment’s data format to the library’s internal structure. This means you never need to change library code when you move to a new experiment, lab, or task variant — you just write a new config.

The config defines four things:

  1. Where your files are and how they’re organised on disk

  2. What your CSV columns are called and how to interpret them

  3. How your task works (boundary, stimulus range and scale, choice encoding)

  4. Your vocabulary: cohorts, session types, session presets, sessions to ignore

It covers two-alternative tasks (2-AFC) and go/no-go alike — see Go/no-go below for the two things that differ.

Minimal Config#

The absolute minimum config that will load data:

project:
  name: "My Experiment"

reader:
  type: csv_folders
  data_dir: "/path/to/data"       # relative paths resolve against this file's folder

task:
  choice_mapping:
    type: "identity"              # choices are already 0/1
    no_response_value: -1         # the raw value that means no response (null if none does)

columns:
  trial_number:
    csv_name: "Trial_Number"
    dtype: int
  stimulus:
    csv_name: "Stimulus"
    dtype: float
  choice:
    csv_name: "Choice"
    dtype: int
  outcome:
    csv_name: "Outcome"
    dtype: str
  correct:
    csv_name: "Correct"
    dtype: bool

Which columns are required is decided by your config, not by the library: any column you list without optional: true must be present in the CSV. Structurally, only trial_number is hard-required by the loader; the example above also makes stimulus, choice, outcome, and correct required simply by listing them as non-optional, which is the typical choice for a 2-AFC task. If your CSV uses different names, just change the csv_name values; to make any of these tolerated-when-missing, add optional: true.

Full Config Reference#

Unknown keys and custom:#

load_config checks every key it reads. A misspelt or unknown key raises ConfigError naming the section, the key, the valid keys and the closest match, instead of being ignored. The top-level keys are project, reader, animal_metadata, task, columns, session_metadata, extra_columns, session_types, session_presets, sessions_to_ignore, cohorts and custom. Keep anything your project needs in the same file under custom:; the library never reads it.

project#

project:
  name: "My Experiment"                  # Project name (for display)
  description: "2-AFC auditory task"     # Optional description
  experimenter: "SS"                     # Optional: whose data (default empty)

name and description are labels. experimenter goes into every trial’s key (see Session ids), so data from two people never share keys even when their animals have the same names; an experimenter entry in the animal metadata overrides it for that animal.

reader#

Where the trial tables come from. A reader finds sessions and reads their tables; everything else in this file (columns, task, metadata) applies the same way whichever reader you use. Relative paths in the config resolve against the config file’s folder, and $ENV_VARS are expanded.

type: csv_folders (the default): one folder per animal, one sub-folder per session.

reader:
  type: csv_folders
  data_dir: "/path/to/data"
  behaviour_file: "trial_summary*.csv"
  date_regex: "(?P<year>\\d{4})_(?P<month>\\d{1,2})_(?P<day>\\d{1,2})"

data_dir/
├── A01/                          ← an animal: every sub-directory of data_dir
│   ├── TASK_A01_2026_1_15/       ← a session: its date is read by date_regex
│   │   └── trial_summary.csv     ← behaviour_file
│   ├── TASK_A01_2026_1_16/
│   │   └── trial_summary.csv
│   └── ...
└── A02/
    └── ...

Field

Default

Description

data_dir

"."

Folder holding one sub-folder per animal

behaviour_file

"trial_summary*.csv"

Glob for the CSV(s) inside a session folder

date_regex

"(\\d{4})_(\\d{1,2})_(\\d{1,2})"

Reads the date from a session’s name: named groups year, month, day (or three positional groups first), and optionally hour, minute, second for the start time

merge_files

true

The files in one session folder are pieces of one session (a restarted run), merged in name order with trial numbers renumbered. false: each file is a session of its own, dated by its file name (or the folder’s when the file name has no date)

drop_last_row

true

Drop each file’s last row (a run that stops can leave it half-written)

min_trials_per_file

10

Skip a file with fewer rows than this; a session left with no file is skipped

A file that cannot be parsed raises, and so does a session whose date cannot be read; with load_experiment(..., strict=False) they are skipped with a warning instead.

Several sessions on one day. Each session folder is a session, so a second folder with the same date is a second session. To order them, let date_regex capture the time as well:

reader:
  date_regex: "(?P<year>\\d{4})_(?P<month>\\d{2})_(?P<day>\\d{2})_(?P<hour>\\d{2})(?P<minute>\\d{2})"

Without a time, sessions on the same day sort by name. If your rig writes each session as its own file in one folder per day, set merge_files: false. Each session’s id says when it ran (see Session ids), so sessions_to_ignore and session_types can name one session as well as a whole day.

type: table: every trial of every session in one table, with columns naming the animal and the session and dating it.

reader:
  type: table
  path: "all_trials.parquet"          # .csv, .tsv or .parquet (Parquet needs pyarrow)
  animal_column: "Mouse"
  session_column: "Session"
  date_column: "Date"
  start_column: "Start"               # optional: orders sessions within a day

Sessions keep their order of first appearance, and a session’s rows keep table order.

A reader of your own, in code: any function that takes the config and yields RawSession objects, passed as load_experiment(config, reader=...). A reader in EXTENDING.md has a complete one that runs.

Discovering sessions and loading a subset#

The Python examples from here on run on a small tree that this block writes, with the config.yaml that maps it: two animals, each with a training and a task session. With data of your own, skip it.

from pathlib import Path

import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
for animal_id in ('A01', 'A02'):
    for day, stage in (('2024_03_15', 'training'), ('2024_03_16', 'task')):
        folder = Path('data') / animal_id / day
        folder.mkdir(parents=True)
        stimulus = rng.uniform(-1, 1, 60)
        pd.DataFrame({'Trial_Number': range(1, 61), 'Stim': stimulus, 'Stage': stage,
                      'Choice': (stimulus + rng.normal(0, 0.3, 60) > 0).astype(int)}).to_csv(
            folder / 'trial_summary.csv', index=False)

Path('config.yaml').write_text(r"""
project: {name: guide}
reader:
  type: csv_folders
  data_dir: data
  behaviour_file: trial_summary*.csv
  date_regex: '(\d{4})_(\d{1,2})_(\d{1,2})'
task:
  choice_mapping: {type: identity, no_response_value: null}
columns:
  trial_number: Trial_Number
  stimulus: Stim
  choice: Choice
session_metadata:
  stage: {csv_name: Stage, dtype: str}
""")

discover_sessions(config) lists every session the reader finds without loading trials: the identity columns every session table shares (session_id, animal_id, experimenter, date, start, source_id, source), whether sessions_to_ignore lists it, the session_metadata fields peeked from each session’s first row, the task, the session type where it can be decided without reading trials, and any related files a reader attached (file_<name> columns). laser=True also reads the laser column, so derived types (‘opto’ or ‘regular’) are filled in; peek=False reads no trial file at all. Filter the table like any DataFrame and load only those sessions:

from behav_utils import discover_sessions, load_experiment

table = discover_sessions('config.yaml')
chosen = table[(table.stage == 'task') & ~table.ignored]
experiment = load_experiment('config.yaml', sessions=chosen)

The ids are the ones loading gives. An id the reader does not find raises (warns with strict=False), and sessions_to_ignore still applies. A saved store’s manifest (read_manifest) is the same table, filtered the same way and passed to load_store(path, sessions=...). After loading, animal.session_table and experiment.session_table start with the same identity columns.

Session ids#

Every session gets an id from its animal, date and start time: A01_20240315, or A01_20240315T0930 when the reader knows the start time. Sessions that would still share an id (several on one day with no time, or with the same time) are numbered A01_20240315_1, A01_20240315_2 in name order, with a warning, because adding or removing one renumbers the rest; capturing the time in date_regex avoids that. Ids are given before any session is ignored, so ignoring one never renames another. The reader’s own name for a session (its folder, its value in the table) stays in session.source_id.

Each trial’s key (TrialArrays.trial_key) holds the session’s hash of experimenter, animal and session id in the upper 43 bits and the trial number in the low 20, the same on every load and machine and unique across animals. Trial numbers must be unique within a session (repeats raise, or with strict=False are renumbered from 1) and below 1,048,576.

animal_metadata#

animal_metadata: "animal_metadata.json"     # {"A01": {"genotype": "het"}, ...}

Per-animal attributes, merged into AnimalData.metadata. Without this key, the csv_folders reader still picks up animal_metadata.json in data_dir when it exists.

task#

Defines the experimental paradigm.

task:
  boundary: 0.0                    # Category boundary, in the CSV's stimulus units
  stimulus_range: [-1.0, 1.0]      # [min, max] of the stimulus, in the CSV's units
  stimulus_scale: "linear"         # "linear" or "log": the axis the stimulus is mapped on
  type: "two_afc"                  # the task: what counts as correct (see below)
  b_side: "positive"               # two_afc: category B is the positive side of the boundary
  on_boundary: "A"                 # two_afc: a stimulus exactly on the boundary

  choice_mapping:
    type: "spatial_to_category"
    no_response_value: 0
    contingency_field: "response_mapping"
    contingency_rules:
      A_left_B_right:
        -1: 0
        1: 1
      A_right_B_left:
        -1: 1
        1: 0

The stimulus axis#

Every statistic, readout and plot in the library works on one normalised stimulus axis: [-1, 1] with the category boundary at 0. Binning, the psychometric fit bounds, the update-matrix grid and the hard/easy split (|stimulus| < 0.3) all assume it. The loader maps your raw stimulus onto it from boundary, stimulus_range and stimulus_scale, piecewise linearly on the chosen scale:

boundary        → 0
stimulus_range  → -1 and +1 (an asymmetric range still puts the boundary at 0)
stimulus_scale  → "log" takes the logarithm first (frequencies, contrasts)

TrialData.stimulus is the normalised value; the value as read from the CSV is kept in TrialData.stimulus_raw (and stimuli_raw in pool_arrays). With the defaults — range [-1, 1], boundary 0, linear — the mapping is the identity, so data already on that axis is untouched. boundary must lie strictly inside stimulus_range; a log scale needs a positive range.

type: what counts as correct#

type names the task, and the task alone decides each trial’s category, its correct response and its score; nothing in the CSV overrides it. Each type takes its own settings, checked against it:

type

settings

correct response

two_afc (default)

b_side: positive (default) or negative, the side of the boundary that is category B; on_boundary: A (default), B or unscored, for a stimulus exactly on it

the category

go_nogo

go_side: positive (default) or negative; on_boundary: no_go (default), go or unscored

go (1) on the go side, withhold (0) on the other; a blank response that is not an abort is a withhold

on_boundary: unscored suits a rig that rewards at random on the boundary: those trials have no correct response and are left out of accuracy. Every trial ends with an outcome code in TrialData.outcome (behav_utils.Outcome: ERROR 0, CORRECT 1, NO_RESPONSE 2, ABORT 3, UNSCORED 4), and TrialData.correct is outcome == CORRECT.

choice_mapping#

How raw choice values from the CSV get converted to category space (0=A, 1=B, NaN=no response).

type options:

Type

When to use

What it does

"spatial_to_category"

Choices are spatial (left/right) and need converting using a contingency rule

Reads contingency from session metadata, applies mapping

"identity"

Choices are already 0/1 in the CSV

Just marks no-response values as NaN

"none"

You don’t want any conversion

Stores raw values as-is

Fields:

Field

Description

no_response_value

Raw value that means no response (→ NaN). Required for identity and spatial_to_category whenever a choice column is mapped; null when no raw value does (blank cells are always no-responses). Nothing is assumed: a default of 0 would turn every A choice in a 0/1 column into a no-response.

contingency_field

spatial_to_category only, required: the session metadata field whose value picks the rule

contingency_rules

Dict of {contingency_name: {raw_value: category_value}}

Example: Choices are already 0/1:

task:
  choice_mapping:
    type: "identity"
    no_response_value: -1    # -1 in CSV means no response

Example: No conversion needed:

task:
  choice_mapping:
    type: "none"

Example: Left/right with one fixed mapping (no contingency varying across sessions): map the raw values in the column itself and use identity; spatial_to_category needs a session-metadata field to pick the rule from, and warns and keeps the raw values when the field is missing.

columns:
  choice:
    csv_name: "Side"
    dtype: float
    mapping: {-1: 0, 1: 1, 0: .nan}   # left → A, right → B, 0 (no response) → missing

task:
  choice_mapping:
    type: "identity"
    no_response_value: null           # no-responses are already missing after the mapping

tasks and task_by#

Sessions of another kind in the same experiment (go/no-go pretraining before 2-AFC, say) get their own task block, named under tasks: and picked by a session-metadata field:

tasks:
  pretraining:                 # the default task block with these keys replaced
    type: go_nogo
task_by:
  field: stage                 # a session_metadata field
  values: {GNG: pretraining}   # its value → a name under tasks

An alternative starts from the default task: block: keys it sets replace the default’s (a choice_mapping replaces the default’s whole), and the task’s own settings carry over only while the type stays the same. Sessions whose value is not listed use the default; session.task_name and the session table’s task column say which a session got.

scoring#

A mapped correct or outcome column is never used as the score. It is kept (TrialData.correct_recorded, outcome_recorded) and checked against the task’s score, session by session:

scoring:
  on_mismatch: warn            # warn (default), raise, or ignore
  outcome_labels: {Correct: correct, Incorrect: error, Miss: no_response, Abort: abort}

The recorded outcome is compared only through outcome_labels; labels it does not list are skipped. A disagreement names the session, the number of trials and the first ones; every statistic uses the task’s score.

columns#

Maps your CSV column names to behav_utils internal names. This is the core of the config — get this right and everything works.

Typical (non-optional) columns#

A standard 2-AFC config lists these as non-optional, so they must be present in the CSV. Only trial_number is structurally required by the loader — the rest are required because this config lists them without optional: true. Mark any of them optional: true if your task lacks them:

columns:
  trial_number:
    csv_name: "Trial_Number"     # Your CSV's column name
    dtype: int

  stimulus:
    csv_name: "Stim_Relative"
    dtype: float

  choice:
    csv_name: "Choice"
    dtype: int

  outcome:
    csv_name: "Trial_Outcome"
    dtype: str

  correct:
    csv_name: "Correct"
    dtype: bool

Column mapping format#

Each column mapping can be either a simple string (just the CSV column name) or a full specification:

columns:
  # Simple form (assumes dtype: float, required)
  stimulus: "Stim_Relative"

  # Full form
  stimulus:
    csv_name: "Stim_Relative"    # Column name in your CSV
    dtype: float                  # Expected type: float, int, str, bool
    optional: false               # If true, missing column is OK
    default: null                 # Default value when column missing or NaN
    mapping: null                 # Value mapping (see below)

dtype#

Type

Behaviour

float

Numeric conversion via pd.to_numeric. NaN for unparseable values.

int

Numeric conversion, then cast to int. NaN → default value (0 if not specified).

str

String conversion. NaN → empty string.

bool

Boolean conversion. Handles True/False strings and 0/1 integers.

optional and default#

columns:
  reaction_time:
    csv_name: "Response_Latency"
    dtype: float
    optional: true          # Won't error if column is missing from CSV
    default: null           # Fills with NaN when missing (null = NaN for floats)

  opto_on:
    csv_name: "Opto_On"
    dtype: bool
    optional: true
    default: false          # Fills with False when missing

If optional: false (the default) and the column is missing from the CSV, loading will raise an error with a clear message telling you which column is missing.

mapping (value mapping)#

Converts raw CSV values to different values during loading:

columns:
  choice:
    csv_name: "Response"
    dtype: str
    mapping:
      left: -1
      right: 1
      none: 0

This reads the Response column, and wherever it says "left" it becomes -1, "right" becomes 1, etc.

Mapping is applied before dtype conversion, so you can map strings to numbers.

Common optional columns#

Here are columns you might want to add depending on your experiment:

columns:
  # Reaction time
  reaction_time:
    csv_name: "Response_Latency"
    dtype: float
    optional: true

  # Abort / broken fixation
  abort:
    csv_name: "Abort_Trial"
    dtype: bool
    optional: true
    default: false

  # Optogenetic manipulation
  opto_on:
    csv_name: "Opto_On"
    dtype: bool
    optional: true
    default: false

  # Stimulus distribution
  distribution:
    csv_name: "Distribution"
    dtype: str
    optional: true
    default: "uniform"

Any column name you use here becomes accessible via session.trials.get_field('column_name') or appears in session.trials.optional_fields.

Event times and the clock#

A column mapped under a name starting with t_ is an event time: t_trial_start, t_stim_on, t_response, t_reward, whatever the rig records. Event times and reaction_time are converted to seconds and kept on the recording clock, not re-zeroed, so another recording on the same clock (video, pupil, imaging) lines up with the trials directly. They are stored in trials.events under the names given here, and session.clock names the clock.

clock:
  name: rig                    # which clock the times are on
  unit: s                      # the unit the files use: s (default), ms or us
  on_problem: warn             # warn (default), raise or ignore
  order: [t_trial_start, t_response]   # optional: the order events happen within a trial

columns:
  t_trial_start: {csv_name: Trial_Start_Time, dtype: float}
  t_response: {csv_name: First_Lick_Time, dtype: float, optional: true}
  reaction_time: {csv_name: RT, dtype: float, unit: ms}    # a column can override clock.unit

Each session is checked for an event column going backwards across trials (the clock restarted, for example at a file boundary when files are merged, or passed midnight on a clock that counts from midnight), negative reaction times, and trials out of order. Each kind of problem gives one warning naming the first trial, or an error with on_problem: raise. An optional event column missing from a file is filled with NaN, so every session has the same events; a required one that is missing fails the session.

session_metadata#

Columns that are constant within a session (task parameters, not trial data). Extracted from the first row of each CSV.

session_metadata:
  animal_id:
    csv_name: "Animal_ID"
    dtype: str

  stage:
    csv_name: "Stage"
    dtype: str

  response_mapping:
    csv_name: "Response_Mapping"
    dtype: str

  response_window:
    csv_name: "Response_Window"
    dtype: str
    optional: true
    parse_timespan: true        # Parse "00:00:10" → 10.0 (seconds)

parse_timespan#

Set parse_timespan: true for columns that contain time values as strings in HH:MM:SS or HH:MM:SS.ffffff format (common with Bonsai). The loader will convert them to float seconds.

session_metadata:
  sound_duration:
    csv_name: "Sound_Duration"
    dtype: str
    optional: true
    parse_timespan: true     # "00:00:01.500000" → 1.5

Session metadata is accessible via:

session = experiment.get_animal('A01').sessions[0]
session.metadata.stage                    # attribute access
session.metadata.get('response_mapping') # dict access
session.metadata.fields                   # raw dict

A field named session_type sets the session’s type from its first row (see session_types); the column is read only when it is mapped here.

extra_columns#

CSV columns to load but not map to specific fields. They end up in session.trials.extra['column_name'].

extra_columns:
  - "Trial_End_Time"
  - "Running_Score"

Any column in the CSV that isn’t in columns or session_metadata is also automatically stored in extra — so extra_columns is just for being explicit about which unmapped columns you care about.

cohorts#

Named lists of animal ids. The library only stores them; a project uses them to pick which animals a report or a notebook covers. Read with behav_utils.config.load_cohorts(path) (import-safe, touches nothing else).

cohorts:
  pilot:    [A01, A02, A03]
  main:     [A04, A05, A06, A07]

Per-animal attributes (group, sex, genotype, …) do not go here: put them in <data root>/animal_metadata.json ({"A01": {"group": "control"}, …}); they are merged into animal.metadata at load time.

session_types#

Session types the data cannot tell on its own. A session’s type comes from, in this order:

  1. this block: your lists, per animal and date;

  2. a session_type field mapped under session_metadata (a column the rig writes);

  3. the trials: 'opto' if the session has any laser trial, otherwise 'regular'.

A list overrides a mapped column, with a warning when the two differ, and session.session_type_source says which of the three set the type ('config', 'column' or 'derived'). A column is read only when it is mapped.

session_types:
  sham:                              # type name — yours
    A01: [20240315, 20240316]
    A02: 20240301                    # a single date is fine
  washout:
    A01: [20240320]
  control_site: {}                   # declared with no dates: a value the session_type column may hold

An entry is a date (YYYYMMDD), covering every session that day, or a session id without the animal prefix ('20240315T0930', '20240315_2'), covering that one session. Quote entries that contain an underscore: unquoted, YAML reads 20240315_2 as the number 202403152, and the config refuses it. A type read from the column that is neither regular, opto nor a name in this block gives one warning per value, since it is usually a typo; declare it here, with no dates, if it is meant. A session listed under two types takes the later one, with a warning. The type is what select_sessions(session_type=…) and exclude_types=(…) filter on, and what session.session_type / animal.session_table show.

session_presets#

Named session selections, registered at load time and used as select_sessions(animal, preset='…'). Each preset is a set of SessionFilter fields:

field

meaning

stage

one stage name or a list (OR)

distribution

one distribution label or a list (OR)

session_type

keep only this type (or list); overrides exclude_types

exclude_types

types to drop, e.g. [sham, washout]

min_accuracy, max_accuracy

accuracy over valid trials

min_trials

valid trials per session (default 10)

first_n, last_n, last_fraction

take the first/last N sessions, or the last fraction, of what remains (applied before the quality filters)

last_n_qualifying

the last N sessions that pass the quality filters (applied after min_accuracy / min_trials)

after_session_idx, before_session_idx, session_indices

by position

exclude_opto

drop sessions that contain opto trials

 
session_presets:
  expert:
    stage: task
    distribution: uniform
    min_accuracy: 0.70
    last_fraction: 0.50
    exclude_types: [sham, washout]
  naive:
    stage: task
    first_n: 5
    exclude_types: [sham, washout]

Order of application: stage → distribution → session type or exclusions (exclude_opto, exclude_types) → index range → first_n / last_n / last_fraction → accuracy and trial-count thresholds → last_n_qualifying → custom filter. So last_n: 5 with exclude_types gives the last five sessions that are not excluded. select_sessions(..., preset=…, **overrides) lets a call override single fields.

A preset is resolved on the animal’s own config first (the ExperimentData it was loaded with keeps its session_presets), then in the process-wide registry (register_preset). Two experiments loaded in one notebook therefore never see each other’s presets.

sessions_to_ignore#

Sessions dropped at load time — never read, never built, never in a saved store. Same shape as one session_types entry: {animal_id: [entries]}, an entry being a date (every session that day) or a session id without the animal prefix (that session).

sessions_to_ignore:
  A03: [20240228]            # rig fault

Go/no-go#

Set the task type and say which side of the boundary is go:

task:
  type: go_nogo
  go_side: positive            # tones above the boundary are go

The task scores a lick to a go stimulus and a withhold to a no-go stimulus as correct. A blank response that is not an abort is a withhold, so it needs no mapping; set choice_mapping.no_response_value: null unless the rig writes a separate value for “nothing recorded”. With stimulus_scale: log for frequencies the psychometric curve is P(go | log f).

Statistics declare what a task must provide. On go/no-go, side_bias and accuracy_b_minus_a are refused in favour of go_bias and hit_minus_cr_rate; the multi-trial history models (logistic_history, history_interaction_r2) have no go/no-go version; everything else applies, the one-trial history statistics reading go or withhold after a correct or an error trial, and dprime/criterion being the standard hit-versus-false-alarm pair. docs/stats_reference.md lists what each statistic needs. docs/config_examples/go_nogo_minimal.yaml is a complete, loadable example.

Continuous responses#

A task whose answer is a value, such as a rat that sees a dot at x on a line and pokes at y, is the reproduction task: correct when |response − stimulus| ≤ tolerance.

task:
  type: reproduction
  tolerance: 0.1                 # on the library's axis: here 5 cm on a 100 cm line
  stimulus_range: [0, 100]       # the line, in the units the files use
  primary_stimulus: stimulus
  primary_choice: choice
  choice_mapping: {type: identity, no_response_value: null}
columns:
  stimulus: {csv_name: DotX, dtype: float}
  choice: {csv_name: PokeX, dtype: float}    # the response: still called choice, in every family

Stimulus and response both go through one linear map (on the linear or log scale) from stimulus_range onto [-1, 1], centred on the range’s midpoint, so a distance means the same everywhere on the line and the tolerance is given on that axis (0.1 is a twentieth of the range). There is no category boundary: leave boundary out, and keep choice_mapping at identity. A response outside the range is kept as recorded, with a warning.

The family’s statistics are response_bias, error_sd, mean_abs_error, response_slope (the pull towards the middle) and serial_bias (the pull towards the previous trial’s stimulus, with the pull towards the middle kept out of it); accuracy is the share within the tolerance, and the reaction-time statistics apply. Its readouts are the response curve, the error distribution and the serial-bias curve, each with its plot. The 2-AFC statistics are refused on it, and these on 2-AFC. docs/config_examples/reproduction.yaml is a complete, loadable example.

Complete examples#

Four complete, loadable configs, each for a different kind of experiment:

  • config_examples/orientation_discrimination.yaml — visual orientation discrimination (different lab)

  • config_examples/go_nogo_minimal.yaml — auditory go/no-go (minimal columns)

  • config_examples/unusual_encoding.yaml — existing dataset with unusual encoding

  • config_examples/reproduction.yaml — a continuous task: reproducing a dot’s position on a line

Check any of them with python -c "from behav_utils import load_config; load_config('docs/config_examples/<file>')".

Validation#

Check a new config in three steps, cheapest first. Each one raises with a message that names the problem.

from behav_utils import discover_sessions, load_config, load_experiment

config = load_config('config.yaml')
table = discover_sessions(config)
print(table[['session_id', 'animal_id', 'date', 'source']])
experiment = load_experiment(config, sessions=table.head(1))

load_config checks every key, and a misspelt one raises ConfigError with the closest valid key, for example unknown key 'behavior_file' (did you mean 'behaviour_file'?). discover_sessions lists the sessions the reader finds, with the ids and dates that loading will give them, without reading any trials: an empty table, a missing animal or a wrong date points at the reader: block (data_dir, behaviour_file, date_regex). Loading one session then reads its file through columns:. A column listed without optional: true that the file lacks stops the load with an error naming it (missing required columns ['RT']); fix its csv_name. Columns the config does not map are kept unchanged in session.trials.extra.

Troubleshooting#

“missing required columns [‘X’]” Your CSV uses a different column name. Check csv_name in your config matches exactly (case-sensitive).

“Unknown contingency ‘X’” Your CSV has a contingency value not listed in contingency_rules. Add it to the config.

Dates not parsing correctly Check date_regex matches your directory naming convention. Use named groups (?P<year>...) for clarity. Test with:

import re
match = re.search(config.reader.date_regex, "2024_03_15")      # one of your session folders' names
print(match.groups())

TimeSpan columns showing as strings Add parse_timespan: true to the session_metadata entry.

Values look wrong after loading Check mapping — value mappings are applied before dtype conversion. If your CSV has "Left" and you’re mapping to -1, make sure the mapping key matches exactly: Left: -1 not left: -1 (YAML is case-sensitive for string keys).

Too many NaN values Check whether your CSV has empty cells, "NA" strings, or unusual missing value indicators. The loader uses pd.to_numeric(errors='coerce') for floats, which converts unparseable values to NaN.
