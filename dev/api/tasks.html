behav_utils.tasks#

behav_utils.tasks — what counts as correct.

A Task decides each trial’s category, its correct response and how a response is scored, for arrays of trials. Every session carries one, built from the config’s task: block (or a named alternative in tasks:), and the loader scores every trial with it; recorded correct/outcome columns are checked against that score, never used instead of it.

The built-in tasks are TwoAFC (two categories; b_side says which side of the boundary is B), GoNoGo (a blank response is a withhold) and Reproduction (a continuous response, correct within tolerance of the stimulus). Outcome holds the codes in TrialData.outcome (Outcome.CORRECT, Outcome.ABORT, …).

Add a task with a frozen dataclass subclass of Task and @register_task (see EXTENDING.md).

Each task declares capabilities; statistics and readouts declare what they need, and require raises RequirementError (naming any counterpart) when a task lacks it.

Stimulus distributions (Uniform, TruncatedNormal, Discrete, or a StimulusDistribution subclass) say how a design draws stimuli and what an observer believes about them.

class behav_utils.tasks.Task[source]#

A task: categories, the correct response and scoring, for arrays of trials.

Subclasses are frozen dataclasses whose fields are the task’s parameters (what a config sets), with a class-level name and the decorator register_task. They implement category and truth; complete_responses and score have defaults that suit most tasks.

capabilities names what the task provides (see CAPABILITIES); statistics and readouts declare what they need, and require checks one against the other. The names are open: a task of your own can add its own, e.g. capabilities = TwoAFC.capabilities | {'cue'}.

Variables:

  • name (ClassVar[str]) – The task’s name in a config’s task.type (class-level).

  • capabilities (ClassVar[frozenset]) – What the task provides, as a frozenset of capability names (class-level).

class behav_utils.tasks.TwoAFC(b_side='positive', on_boundary='A')[source]#

Two-alternative forced choice.

Category B is the stimuli on b_side of the boundary (default the positive side), A the rest, and the correct response is the category. A stimulus exactly on the boundary counts as on_boundary: ‘A’ (the default), ‘B’, or ‘unscored’ (no correct response, as on a rig that rewards at random there).

Variables:

  • b_side (str) – The side of the boundary that is category B, ‘positive’ or ‘negative’.

  • on_boundary (str) – What a stimulus exactly on the boundary counts as: ‘A’, ‘B’ or ‘unscored’.

class behav_utils.tasks.GoNoGo(go_side='positive', on_boundary='no_go')[source]#

Go/no-go.

The correct response is go (1) to stimuli on go_side of the boundary and no-go (0, withholding) to the rest. A blank response that is not an abort is a withhold, so it is scored, not lost. A stimulus exactly on the boundary counts as on_boundary: ‘no_go’ (the default), ‘go’ or ‘unscored’.

Variables:

  • go_side (str) – The side of the boundary where go is correct, ‘positive’ or ‘negative’.

  • on_boundary (str) – What a stimulus exactly on the boundary counts as: ‘no_go’, ‘go’ or ‘unscored’.

class behav_utils.tasks.Reproduction(tolerance=0.1)[source]#

Reproduce the stimulus.

The correct response is the stimulus itself, and a response is correct when it lies within tolerance of it, the boundary included, on the library’s axis: a rat that sees a dot at x on a line and pokes at y is correct when |y − x| ≤ tolerance. There are no categories (category is NaN). The statistics reference lists the statistics for continuous responses.

Variables:

tolerance (float) – The largest distance from the stimulus, on the library’s axis, that still counts as correct; must be positive.

Parameters:

tolerance (float)

class behav_utils.tasks.Outcome(*values)[source]#

How a trial was scored; TrialData.outcome holds these as small integers.

Variables:

  • ERROR – Responded, and not with the correct response.

  • CORRECT – Responded with the correct response.

  • NO_RESPONSE – The response window passed with no response, where withholding is not an answer.

  • ABORT – The trial ended before the response window.

  • UNSCORED – Responded, but the task defines no correct response for this trial.

exception behav_utils.tasks.RequirementError[source]#

A statistic or readout was asked of a task that lacks a capability it needs.

behav_utils.tasks.require(task, needs, what, instead=None)[source]#

Raise RequirementError unless task declares every capability in needs.

what names the statistic or readout. instead maps a capability to a counterpart to suggest when the task has it ({'withhold': 'go_bias'}). The message says what is missing, what the task has, the counterpart or that there is none, and flags a name no registered task declares (a typo?).

Parameters:

  • task (Task) – The task to check.

  • needs – The capability names required.

  • what (str) – The statistic or readout asking, named in the message.

  • instead (Mapping[str, str] | None) – Maps a capability to a counterpart to suggest when the task has it; None for none.

Raises:

RequirementError – The task lacks one of needs.

Return type:

None
